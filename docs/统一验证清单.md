# 统一验证清单（README 功能 → 入口 → 证据）

> 环境：Windows，backend `127.0.0.1:8787`（`app-dir backend`，Python 3.12.14）、前端 `127.0.0.1:5173`（Vite dev）、
> 目标 `mock`（无需安装游戏）。全部结论来自本机实测：HTTP 冒烟（`scripts/verify/api_smoke.py`，38 项）、
> CDP 逐页审计（`scripts/verify/cdp-audit2.mjs`，16 路由）、WebSocket 证据探针（`scripts/verify/ws_probe.py`）、
> 界面截图（`scripts/verify/make-shots.mjs` → `docs/screenshots/`）。
> 说明：本机没有可用的视觉模型，界面结论一律用 DOM 断言与接口返回核对，不靠「看起来对」。

## 本轮修复

1. **PvP 图鉴名解析**（`backend/app/pvp.py`）：NRC 预设队用裸名「千棘盔」，图鉴存「千棘盔（本来的样子）」→ 精确匹配 400。新增 `_strip_form()` + `_resolve_row()`（精确 → 去形态后缀 → 前缀 → 唯一包含），analyze/matchup 全部改走它；未知名仍抛「图鉴中不存在: …」（`backend/tests/test_component_bugs.py:109` 依赖该文案）。
2. **PvpView 首屏双请求**：移除 onMounted 里重复的 `analyze()`（与 `watch(team, scheduleAnalyze)` 双发产生两条 400），并由 `memberAt(index)` 按序号取成员，避免后端返回形态名后按名查找失配。
3. **侧栏溢出与空图标**：`rocoui` 的 `nav.rk-side-nav` 固定 320px 导致 133px 溢出；`SideNavItem/SideNavHeader` 的 `v-if="props.icon"` / `hasStructuredContent` 需要布尔属性才渲染插槽，而 App.vue 只给了 `#icon`。修法：`<SideNavHeader icon eyebrow title>`、`<SideNavItem … icon …>`，并用 `:deep([class*="itemIcon"])` 这类属性包含匹配覆盖哈希类名；修后 sider 208px、溢出 0、16 项全部有图标、品牌头「洛克工坊 | Rocogi」可见。
4. **F9/F10/F11 前端热键**（`frontend/src/App.vue`）：原前端无任何热键逻辑。新增页面级 keydown 层（跳过输入框/组合键/overlay），F9 启实时、F10 停实时+追踪、F11 切追踪，附 toast 与侧栏热键提示条。

6. **实时页停止后计数器残留**（`RealtimeView.vue`）：加 `.stat-grid-stale` 压暗与「上次会话」角标。

## 已知偏差（不阻塞交付）

1. **系统级热键的按键注入**：`/api/hotkeys` 的 `RegisterHotKey` 注册成功（`running: true`），但用 `keybd_event` 注入的 F9 在该会话下不产生 `WM_HOTKEY`，`triggered` 保持空。真实键盘按下应正常；Web UI 侧 F9/F10/F11 已可独立实测。
2. **`map` 模拟场景没有独立贴图**：`/api/demo/scene` 的 `map` 用空视野帧叠地图层，识别结果为 `field`，属既有设计，不影响识别节点调试。
3. **需要外部依赖的 12 个 partial 组元**：`capture.windows_window/scene_switch/foreground`、`vision.ocr`（通用中文需 Tesseract）、`input.sendinput/interception/hotkey`、`sift.trajectory/route_plan/external_tracker`、`battle.responder`、`scheduler.capture_fsm` —— 组件图谱里标 partial 属预期，mock 目标下不影响主链路。
4. **一条龙测试残留数据**：多次实测在 `/api/runs` 累积了若干 run，计划本身已还原默认顺序（auto_ball, smart_battle, party_confirm, map_route, battle_ai；前 3 项 enabled）。
